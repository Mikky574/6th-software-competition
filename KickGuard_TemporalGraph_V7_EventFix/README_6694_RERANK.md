# KickGuard 66.9444 Local Rerank

This stage does not retrain the global model. It treats the two leaderboard-proven 66.9444 submissions as anchors and only makes tiny local swaps.

## Inputs

Recommended anchors:

- `V5_feedback_dropbad_116.zip` (66.9444)
- `V5_meta_plus4_124.zip` (66.9444)

Existing diagnostics:

- `work_v7/V7_test_debug.csv`
- `work_v7/V7_1_test_debug.csv`

At least one anchor is required. Both are strongly preferred because their intersection can be protected.

## Run

```bash
python kickguard_6694_rerank.py \
  --base116 /path/to/V5_feedback_dropbad_116.zip \
  --base124 /path/to/V5_meta_plus4_124.zip \
  --work-dir ./work_v7 \
  --output-dir ./rerank_6694
```

Or:

```bash
BASE116=/path/to/V5_feedback_dropbad_116.zip \
BASE124=/path/to/V5_meta_plus4_124.zip \
bash run_6694_rerank.sh
```

## Strategy

1. Keep the 66.9444 submission as the dominant anchor.
2. If both anchors are available, samples positive in both anchors are protected by default.
3. V7/V7.1 probability calibration is ignored; only rank-normalized weak evidence is used.
4. Risk signals are grouped by family to avoid double-counting highly correlated branches.
5. Drops prefer anchor-boundary positives that multiple weak families rank low.
6. Adds prefer negatives supported by the other 66.9444 anchor and ranked high by multiple weak families.
7. Generate same-count swaps of 1-6 samples, preserving the proven positive count.

## Recommended submission order

Use `SUBMIT_ORDER.txt` generated by the script. In general start with:

1. base116 swap2
2. base124 swap2
3. base116 swap3
4. base124 swap3

Do not start from dual-consensus candidates. They modify more of the leaderboard-proven structure and are exploratory.
